# httpjail Rule Format

## Overview

httpjail uses JavaScript expressions to evaluate each outbound HTTP/HTTPS request. The expression must return `true` to allow a request or `false` to block it.

Egressor automatically generates these rule files from your `.egressor.yml` configuration. You should not need to edit the generated files directly.

## Available Variables

httpjail provides these variables in the rule evaluation context:

| Variable | Type | Description | Example |
|----------|------|-------------|---------|
| `host` | string | Request hostname | `"api.github.com"` |
| `method` | string | HTTP method | `"GET"` |
| `path` | string | URL path | `"/repos/owner/name"` |
| `url` | string | Full request URL | `"https://api.github.com/repos/owner/name"` |

## How .egressor.yml Maps to httpjail Rules

Each rule in `.egressor.yml` becomes a boolean expression. Multiple rules are combined with `||` (OR) - a request is allowed if it matches any rule.

### Host Matching

Exact host:
```yaml
- host: registry.npmjs.org
```
Generates:
```javascript
host === "registry.npmjs.org"
```

Wildcard host:
```yaml
- host: "*.github.com"
```
Generates:
```javascript
(host === "github.com" || host.endsWith(".github.com"))
```

### Method Filtering

```yaml
- host: api.example.com
  methods: [GET, POST]
```
Generates:
```javascript
host === "api.example.com" && ["GET", "POST"].includes(method)
```

### Path Filtering

```yaml
- host: api.example.com
  paths: [/api/v1, /api/v2]
```
Generates:
```javascript
host === "api.example.com" && (path.startsWith("/api/v1") || path.startsWith("/api/v2"))
```

### Combined Example

Given this `.egressor.yml`:

```yaml
version: "1.0"
rules:
  - host: registry.npmjs.org
    description: npm registry
  - host: "*.github.com"
    description: GitHub
  - host: api.example.com
    methods: [GET, POST]
    paths: [/api/v1]
    description: Internal API
```

Egressor generates:

```javascript
// Auto-generated by Egressor - do not edit manually
// httpjail rule file: returns true to allow a request, false to block

// Allow requests matching any of these rules:
(host === "registry.npmjs.org") // npm registry
|| ((host === "github.com" || host.endsWith(".github.com"))) // GitHub
|| (host === "api.example.com" && ["GET", "POST"].includes(method) && (path.startsWith("/api/v1"))) // Internal API
```

### Empty Rules

If no rules are configured, the generated file blocks all traffic:

```javascript
// No rules configured - block all traffic
false
```

## httpjail Operating Modes

### Standard Mode

Proxies HTTP/HTTPS traffic through the rule engine. Non-HTTP traffic is not affected.

### Strong Mode (--strong)

Uses nftables to enforce full traffic control:
- All HTTP/HTTPS traffic goes through the rule engine
- DNS (UDP port 53) is always permitted
- All other non-HTTP traffic is blocked

Egressor uses strong mode by default when running with `--docker-run` for container sessions.

## httpjail Command Line

Egressor starts httpjail with these arguments:

```
httpjail --rules <path/to/rules.js> --docker-run <container_id> --strong --port <proxy_port>
```

| Flag | Description |
|------|-------------|
| `--rules` | Path to the generated JavaScript rules file |
| `--docker-run` | Target Docker container ID |
| `--strong` | Enable nftables-based full traffic control |
| `--port` | HTTP proxy listen port |
